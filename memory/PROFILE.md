## 작업 스타일 (관찰된 것)

- **지적이 정확하고 방향 전환이 잦다.** 한 번에 합의되기보다 3~4회 반려를 거쳐 수렴한다.
  → 산출물을 매번 **전면 재작성**하고, **탈락한 안과 사유를 문서에 남긴다.** ("왜 이걸 골랐나" 방어 근거가 된다.)
- "발표에서 공격당할 가능성"을 항상 먼저 본다. → **예상 질문 방어 시트**를 기본으로 만든다.
- 실현 가능성을 냉정하게 본다. 권한·데이터·난도 리스크에 민감하다.
- 트렌드·재미 요소를 중요하게 여기되, **기능과 붙어 있어야** 인정한다.
- **필요한 정보는 작업 전에 먼저 물어보라**고 명시적으로 요구한다. 보고는 **조치한 것 / 제안 / 확인 필요**로 나눠 짧게.
  → 추측으로 채운 칸이 있으면 반드시 그 사실을 밝힌다. 추측 섹션은 결국 질문으로 확인받게 된다 (프로필 `05` 섹션 사례)
