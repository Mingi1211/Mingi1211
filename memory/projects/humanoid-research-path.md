## 연구 주제 검토 결과 (아직 교수님과 확정 전)

1. **Gemini "Unified Contact-Actuation Parameterization"(URDF+YAML만으로 이기종 WBC) → 과대평가로 판단.**
   mc_rtc가 "재작성 없이 URDF로 여러 로봇 배포"를 이미 셀링 포인트로 가짐. 리뷰어가 초록에서 리젝할 위험.
2. 대안으로 제안한 것: **프레임워크를 새로 만들지 말고 기존(TSID/mc_rtc) 위에서 이식성을 측정 → 원인 규명 → 보정 규칙 제안.**
   "측정은 동기, 보정 규칙이 주인공"이어야 accept 구조가 됨 (ASAP, RSS 2025 형태).
3. 프레임워크 레벨 구분: L0 예제 / **L1 로봇별 config 분리(학부 1년 현실선)** / L2 제약 자동 생성(몇 달) / L3 mc_rtc급(불가).
4. AI Worker 스펙 확인: **FFW-SG2 = 스워브 3륜(독립 조향·구동) + 양팔 7-DoF**, `ROBOTIS-GIT/ai_worker` 공개.
   → 비홀로노믹 문제 없음. 좁힌 가설: **"엔드이펙터를 미는 방향에 따라 조향 재배치 정도가 달라 같은 임피던스 사양에도 응답이 달라진다"**.
5. 실행 리스크: G1·사피엔스 도착일 미정 → **시뮬 3형태 + 실기 1대**를 처음부터 설계 기본값으로.
6. 기술 메모: 휠 속도 제약을 가속도 레벨로 올리면 드리프트 → Baumgarte 안정화 필요.
