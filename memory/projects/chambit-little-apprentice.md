## 왜 이 주제인가 (조건과 근거)

사용자가 건 조건:
- **조기졸업(2027-08)이면 4-1 캡스톤은 지원서에 못 씀** → 이번 참빛설계학기를 "미리 하는 캡스톤"으로
- 심사위원이 **"이게 뭐지?"** 하고 물어볼 만한 것. 대기업이 이미 하는 것(빨래 개기 등) 제외
- **WBC·sim-to-real + 이기종 통합 제어기 논문과 이어지는** 주제 (팀 로봇 = 논문의 "또 하나의 이기종")
- **AI Worker 못 씀** → 로봇을 직접 만들거나 사야 함. 예산은 100만 원 근처, 국내 쇼핑몰 링크 확보 필수
- 억지로 기술에 스토리를 끼워맞추지 말 것

핵심 논리:
- 작은 휴머노이드가 정당화되는 유일한 경우 = **몸 자체가 소통 수단일 때** (KASPAR·NAO 아동 연구)
- "로봇이 대신 치우면 아이는 안 배운다" → 아이는 **가르칠 때** 배운다 (EPFL CoWriter, protégé effect)
- 정리는 몸으로 하는 일 → 배우는 쪽도 아이와 닮은 몸 → **작고 약해야** 안전·정당
- 휠베이스라도 **베이스·몸통·양팔을 하나의 제어 문제로 풀면 전신제어**. 조건: 시범·모방 모드에서는 제어가 베이스까지 맡음.
  발표·논문 표기는 **"휠 기반 휴머노이드 전신 제어"** (균형·지면반력 제어는 없다고 정직하게)

## 하드웨어 (B안 기준)

- 15축. 허리 yaw + **허리 pitch(XM430, 상체 무게 받는 최대 부하)** + 머리 tilt(+pan) + 양팔. 팔꿈치 **XC330**(전류 측정 가능)

| 안 | 탈락 사유 (사용자 판단) |
|---|---|
| 도달가능성 기반 베이스 위치 선정 + 팔 제어 | "핀트 못 잡음" — 시간 채우기·기술 나열. **어떤 task를 하는지**가 없음 |

| **LeKiwi** 기반 | 너무 작아 실제 음식 집기·서빙 불가. 한국 공식 판매처 없음 |
