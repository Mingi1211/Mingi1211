## 1. 문제 정의 (Why)

### 현황 조사 — 졸업요건 정보가 최소 4곳에 흩어져 있음

| 필요한 정보 | 현재 확인 경로 |
|---|---|
| 내가 지금까지 딴 학점 | KLAS 로그인 → 대학생활 → 학습결과 → 수강/성적 조회 |
| 졸업 학점 기준·영역별 요건 | **당해학기 수강신청 자료집 PDF 19~31페이지** |
| 학부/전공별 세부 요건 | 학과 홈페이지 및 학과사무실 안내 |
| 영어인증·전공배정 등 부가 요건 | 별도 공지 / 교육지원팀 문의 (02-940-5021) |

> 1차 조사는 공개 검색 결과 기반이며, 각 요건의 최신 기준은 팀이 자료집 원문으로 직접 확인한다.

### 한 문장 문제 정의
> **"내가 졸업할 수 있는가"를 확인하려면 학생은 PDF 자료집과 성적표를 띄워놓고 직접 엑셀로 계산해야 한다.**

### 이 문제가 진짜인 이유
- KLAS는 **"지금까지 취득한 학점"** 만 보여준다. **"앞으로 무엇을 들어야 하는가"** 는 아무도 알려주지 않는다
- 졸업사정은 통상 졸업 직전에 이뤄져, 1~3학년은 자기 상태를 점검할 수단이 사실상 없다
- 전과·복수전공·편입·군휴학 복학생은 적용 요건이 입학년도별로 달라 난이도가 급격히 올라간다
- 광운대 로봇학부는 전공배정(정보제어 / 지능시스템 / AI로봇) 구조라, **전공 선택이 졸업요건에 직접 영향**을 준다

### 공감 근거
"졸업 못 할까 봐 불안하다"는 특정 학년의 문제가 아니라 **전 학년 공통 정서**다. 사용자를 설득할 필요가 없는 주제다.

## 2. 무엇을 만드는가 (What)

### 핵심 설계 판단 ⚠️ — 권한 문제를 구조적으로 제거
**우리는 학교 시스템에 접속하지 않는다.**
- 사용자가 **자기 성적표를 복사해 붙여넣거나**, 이수 과목을 체크한다
- 요건 규칙은 **공개된 수강신청 자료집을 팀이 읽어 DB로 옮긴다**
- 학교 DB 연동 0 / 계정 연동 0 / 크롤링 0 / 개인정보 서버 저장 0

> 발표에서 "학교 허가는 받았나요?"라는 질문에 **"이 서비스는 학교 시스템과 통신하지 않습니다"** 한 문장으로 끝난다. 이것이 이 주제를 선택한 가장 큰 이유다.

### MVP 기능 (반드시 구현)

1. **성적표 붙여넣기 파싱** — KLAS 성적 조회 화면을 복사해 붙여넣으면 과목명·학점·이수구분·성적을 자동 인식. 인식 실패 항목은 수동 수정 가능
2. **요건 진단 대시보드** — 총 이수학점 / 전공필수 / 전공선택 / 교양 영역별 / 영어인증 / 기타 요건을 **충족·부족·확인필요** 3색으로 시각화. 부족분은 "전공선택 9학점 부족"처럼 숫자로
3. **남은 학기 로드맵** — 남은 학기 수에 맞춰 "언제 무엇을 들어야 하는가"를 학기별로 배치. 선수과목 관계 반영
4. **What-if 시뮬레이터** — "복수전공을 하면?", "이번 학기에 이 과목 대신 저 과목을 들으면?", "한 학기 휴학하면?"을 즉시 재계산
5. **근거 표시** — 모든 판정에 **출처(자료집 O페이지) + 최종 확인일** 을 함께 표기. 틀릴 수 있음을 전제로 설계
6. **결과 공유·저장** — 진단 결과를 이미지/링크로 저장해 학과사무실 상담 시 지참

### 확장 기능 (여유 시)

7. **학기 부담도 미리보기** — 담은 과목 조합의 주차별 과제·시험·팀플 부담 히트맵 (별도 후보 ②를 부가 기능으로 흡수)
8. **전공배정 가이드** — 로봇학부 3개 전공별 요건 차이와 진로를 비교
9. **요건 변경 알림** — 자료집 개정 시 영향받는 항목 안내
10. **관리자 화면** — 요건 규칙을 코드 수정 없이 갱신

### 범위 밖 (명시적으로 안 함)
- KLAS 계정 연동 / 자동 로그인 / 성적 자동 수집
- 실제 졸업사정 대체 (어디까지나 **참고용 자가진단**)
- 수강신청 매크로 등 학사 시스템에 개입하는 일체의 기능
- 하드웨어·회로·기구 설계

## 3. 그래서 무엇이 좋아지는가 (Value)

- PDF와 엑셀을 오가던 30분짜리 손계산이 **붙여넣기 한 번, 3초**로 바뀐다
- 4학년이 되어서야 알던 사실을 **1학년 때 미리** 알 수 있다
- "그래서 다음 학기에 뭘 들어야 하지?"라는 **행동 가능한 답**을 준다 — 기존 어떤 수단도 주지 않는 것
- 구축한 요건 규칙 DB는 학과·학생회에 넘길 수 있는 **재사용 가능한 산출물**이 된다

---

## 4. 목표 (측정 가능하게)

- 로봇학부·전자공학과·소프트웨어학부 **3개 학부 × 최근 3개 입학년도** 요건 규칙 DB화
- 진단 정확도: 실제 졸업 예정자 **10명 표본에서 학과사무실 확인 결과와 95% 이상 일치**
- 성적표 붙여넣기 → 진단 결과 출력까지 **3초 이내**
- 사용자 테스트 **20명 이상**, "다음에도 쓰겠다" **70% 이상**
- 최종 발표에서 **현장 즉석 붙여넣기 데모 성공**

## 5. 예상 공격 질문 & 방어 (발표 대비) ⭐

이번 주제 선정의 실질적 관건. 팀원 전원이 숙지한다.

| # | 예상 질문 | 답변 |
|---|---|---|
| 1 | **학교 DB 접근 권한은 받았나요?** | 받을 필요가 없습니다. 학교 시스템과 일절 통신하지 않고, 사용자가 자기 성적표를 직접 붙여넣습니다 |
| 2 | **KLAS에 이미 있는 기능 아닌가요?** | KLAS는 "취득한 학점"을 보여줍니다. 저희는 "앞으로 무엇을 들어야 하는가"와 가정 시뮬레이션을 제공합니다. 대상 학년도 다릅니다 |
| 3 | **요건 데이터가 틀리면 책임은?** | 참고용임을 전 화면에 명시하고, 모든 판정에 출처 페이지와 최종 확인일을 표기합니다. 최종 확인은 학과사무실 상담이며, 그 상담을 위한 자료를 만들어 주는 것이 저희 역할입니다 |
| 4 | **개인정보(성적) 유출 위험은?** | 성적 데이터는 브라우저 안에서만 처리하고 서버에 저장하지 않습니다. 회원가입도 없습니다 |
| 5 | **매년 요건이 바뀌면 유지보수는?** | 요건을 코드가 아닌 데이터(규칙 테이블)로 분리해, 관리자 화면에서 비개발자도 갱신할 수 있게 설계했습니다 |
| 6 | **입학년도마다 요건이 다른데 감당되나요?** | 그래서 범위를 3개 학부 × 3개 입학년도로 명시적으로 한정했습니다. 구조는 확장 가능하되 이번 학기 목표는 9개 조합입니다 |
| 7 | **에브리타임이 하면 끝나는 것 아닌가요?** | 전국 서비스는 학교별 요건 차이를 감당하기 어렵습니다. 이 문제는 **한 학교를 깊게 파는 쪽**이 유리한 구조입니다 |
| 8 | **기술적으로 너무 쉬운 것 아닌가요?** | 난도의 핵심은 코드가 아니라 **요건 규칙의 정확한 모델링**입니다. "전공선택 중 3과목 이상은 3000번대" 같은 조건들을 규칙 엔진으로 표현하는 것이 본 프로젝트의 기술적 기여입니다 |
| 9 | **사용자가 없으면 무용지물 아닌가요?** | 사용자 1명이어도 즉시 작동합니다. 다른 사람의 데이터가 필요 없는 구조입니다 |
| 10 | **파싱이 실패하면?** | 실패 항목은 화면에서 직접 수정할 수 있고, 붙여넣기 없이 과목을 체크하는 수동 입력 경로를 항상 제공합니다 |

## 6. 기술 스택 (전부 무료 / 저비용)

- 프론트: React + TypeScript + Vite, 반응형
- **규칙 엔진**: 요건을 JSON/DB 규칙으로 선언하고 평가하는 자체 모듈 (본 프로젝트의 핵심)
- 백엔드: FastAPI 또는 Next.js API Route (요건 규칙 제공 + 관리자 기능)
- DB: PostgreSQL (Supabase 무료 티어) — **성적 데이터는 저장하지 않음**
- 배포: Vercel 무료 티어
- 협업: GitHub(코드·이슈), Notion / Google Drive(자료), Figma(와이어프레임)
- 개발 도구: Cursor, Claude Code

## 9. 위험 및 대응 (Risk)

| 위험 | 대응 |
|---|---|
| **요건 데이터 오류** (프로젝트 최대 리스크) | 학부별 담당자 1차 정리 → 교차 검증 2차 → 졸업 예정자 10명 실제 대조 3차. 모든 판정에 출처·확인일 표기 |
| **입학년도별 요건 분기 폭발** | 3개 학부 × 3개 입학년도 = 9개 조합으로 범위를 못 박고 늘리지 않는다 |
| **성적표 붙여넣기 포맷 변동** | 파서는 보조 수단으로만 취급. 수동 입력 경로를 항상 동등하게 제공 |
| **개인정보 우려** | 성적 데이터는 브라우저 내 처리, 서버 미저장, 회원가입 없음 — 화면에 명시 |
| **난도가 낮아 결과물이 밋밋해짐** | 성과 지표를 코드량이 아닌 **요건 커버리지(9개 조합)와 진단 정확도(95%)** 로 삼는다 |
| 통합 지연 | 매주 화요일 회의에서 `main` 통합 강제, 개인 브랜치 1주 이상 미병합 금지 |

## 10. 제약사항 (Constraints)
- 최종 제출: 12월 초 / 예산: 20만 원 이내 (AI 코딩툴 구독 + 배포·DB 무료 티어 범위 내)
- 학교 학사 시스템에 대한 읽기/쓰기 권한 없음 — 사용자 입력 기반으로만 동작
- 본 서비스는 공식 졸업사정을 대체하지 않는 참고용 도구

## 12. 최종 발표 데모 시나리오 (5분)

1. 문제 제기 — 화면 3개를 한 장에: KLAS 성적표 / 수강신청 자료집 PDF 19페이지 / 학생이 직접 만든 엑셀. **"졸업 가능 여부를 알려면 지금은 이걸 다 띄워야 합니다"**
2. 화면 전환 → 성적표를 **붙여넣기** → 3초 만에 영역별 진단 결과
3. "전공선택 9학점 부족 / 영어인증 미충족"이 근거 페이지와 함께 뜨는 장면
4. **남은 3학기 로드맵** 자동 생성 → "다음 학기에 이 3과목"
5. What-if: **"복수전공을 하면?"** 토글 → 즉시 재계산되는 장면
6. 성과 정리 — 요건 커버리지 9개 조합, 졸업 예정자 10명 대조 정확도, 사용자 테스트 20명 결과
