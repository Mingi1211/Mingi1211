|---|---|

## 2. A안 상세 — `RoboScript`: 자연어로 로봇 동작을 설계하는 웹 시뮬레이터

### 한 줄 정의
> **"컵을 집어서 오른쪽 상자에 넣어줘"라고 입력하면, 그 문장을 로봇 동작 시퀀스로 바꿔주고 브라우저 안 3D 로봇팔이 실제로 실행해 보이는 웹 서비스.**

### 문제 정의 (Why)
- 로봇 프로그래밍 실습은 **실물 장비 대수가 학생 수보다 훨씬 적어** 한 사람당 만질 수 있는 시간이 매우 짧다.
- 입문자는 좌표계·역기구학·좌표 프레임 개념 때문에 "첫 동작 하나" 만드는 데 몇 시간을 쓴다.
- 반대로 산업 현장은 Physical AI / VLA(Vision-Language-Action) 흐름을 타고 **"말로 지시하는 로봇"** 으로 가고 있는데, 학부 실습은 여전히 좌표 하드코딩 단계에 머물러 있다.

### 무엇을 만드는가 (What)
1. **명령 입력** — 한국어 자연어 명령창
2. **행동 시퀀스 변환** — LLM이 사전 정의된 스킬 DSL(`move_to`, `grasp`, `release`, `rotate`, `wait`)의 JSON 시퀀스로 변환
3. **시퀀스 편집 UI** — 변환 결과를 카드 타임라인으로 보여주고, 드래그로 순서 변경·파라미터 수정·삭제 가능 (= AI가 틀려도 사람이 고친다)
4. **3D 실행** — 브라우저 3D 씬(로봇팔 1대 + 테이블 + 블록 3개)에서 시퀀스를 애니메이션으로 재생
5. **실행 가능성 검증** — 도달 범위 초과 / 충돌 / "안 집은 걸 놓으려 함" 같은 오류를 실행 전에 잡아 **이유와 함께** 표시
6. **저장·공유** — 시나리오를 URL 링크로 공유, 과제 제출용으로 사용

### 그래서 뭐가 좋아지는가 (Value)
- 실물 장비 없이 **학생 수만큼 동시에** 로봇 동작 실습이 가능해진다.
- 입문자의 첫 동작 제작 시간이 시간 단위 → 분 단위로 줄어든다.
- "LLM이 만든 계획을 사람이 검토·수정한다"는, VLA 시대에 실제로 필요한 워크플로를 학부 수준에서 체험시킨다.

### 프로젝트 범위 (Scope)

**포함**
- 웹 프론트엔드 + 3D 뷰어 + LLM 연동 백엔드
- 로봇팔 1종(공개 URDF 모델 사용), 스킬 5종, 작업 오브젝트 3~5개
- 정량 평가용 명령 30문항 벤치마크 세트
- 교내 사용자 테스트(로봇학부 학부생 대상) 및 반영

**제외 (명시적으로 안 함)**
- 실물 로봇 구동, 하드웨어/기구 설계, 회로 제작
- 모델 학습(강화학습·VLA 모델 직접 훈련), 카메라 비전 인식
- 다중 로봇, 이동 로봇, 물리 엔진 수준의 정밀 동역학

> 이 "제외" 목록이 핵심입니다. 여기를 흐리면 한 학기에 절대 못 끝냅니다.

### 목표 (측정 가능하게)
- 벤치마크 30문항 중 **24문항(80%) 이상**에서 실행 가능한 시퀀스 생성
- 처음 쓰는 사용자가 **5분 이내** 첫 시나리오 완성
- 사용자 테스트 **15명 이상** 수행 및 개선 반영
- 최종 발표에서 **현장 즉석 입력 데모 성공**

### 기술 스택 (전부 무료/저비용)
- 프론트: React + TypeScript + Vite, 3D는 three.js + URDF 로더
- 백엔드: FastAPI 또는 Next.js API Route
- LLM: Claude / GPT API의 함수 호출(structured output) — 스키마 검증 후 재시도
- DB: PostgreSQL(Supabase 무료 티어)
- 배포: Vercel 무료 티어
- 개발 도구: Cursor, Claude Code, Figma

## 3. 백업 후보 요약

### B안 — 공대 실습실·장비 예약 + 상태 공유
3D프린터·오실로스코프·실습실을 예약하고, 고장/소모품 부족을 신고·공유하는 웹.
- 장점: 수요가 확실하고 난도가 가장 낮음. 실제로 계속 쓰일 가능성 높음
- 단점: 아이디어 차별성이 약하고 발표 임팩트가 낮음

### C안 — 공대 3개 학부 커리큘럼·진로 로드맵 내비게이터
학사 편람의 과목 선수관계를 그래프로 시각화하고, "휴머노이드 제어", "임베디드", "AI 서비스" 같은 진로 트랙별 수강 경로를 추천.
- 장점: 로봇·전자·소프트 3개 학부 팀 구성과 주제가 정확히 일치. 인터랙티브 그래프라 시각적 임팩트가 큼. 데이터는 공개 자료라 수집 리스크 없음
- 단점: 정보 시각화에서 끝나면 "그래서 뭐가 새로운데?" 질문을 받을 수 있음 → 선배 수강 후기/난이도 자체 설문 데이터를 얹어야 함
- **A안이 난도 문제로 흔들릴 경우 10월 초에 이쪽으로 전환 가능**

### D안 — 광운대 주변 자취방 계약 리스크 셀프 체크
계약 전 확인 항목을 단계별 UI로 안내하고, 등기부등본·계약서 사진을 올리면 위험 항목을 체크리스트로 뽑아주는 서비스.
- 장점: 월계동이라는 지역 특수성 + 실제 피해가 존재하는 문제. A팀의 "지역 밀착" 컨셉과 결이 같음
- 단점: 법률적 책임 소지가 있어 "참고용" 고지가 필수. 문서 인식 정확도가 곧 서비스 품질이라 기술 리스크가 A안 못지않음
