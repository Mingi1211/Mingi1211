## 0. 주제 선정 경과

4개 후보(자연어 로봇 시뮬레이터 / 공간·장비 예약 통합 / 커리큘럼 로드맵 / 자취방 계약 체크)를 비교한 결과 **공간·장비 예약 통합**으로 확정.

**선정 사유**
- 로봇 자연어 제어 시뮬레이터 안은 **전공 심화 프로젝트 성격이 너무 강해** 로봇학부 외 팀원의 참여 폭이 좁고, 팀 프로젝트 과목의 취지와 맞지 않아 제외
- 본 주제는 8명 전원이 "사용자이자 조사원"이 될 수 있고, 기술 난도는 낮지만 **자체 데이터 수집의 깊이와 UI 완성도로 승부**할 수 있음 — A팀이 메뉴판을 직접 촬영해 차별화한 것과 같은 구조

## 1. 문제 정의 (Why)

### 현황 조사 결과 — 예약 채널이 5갈래로 쪼개져 있음

| 대상 | 현재 예약·조회 방식 | 문제 |
|---|---|---|
| **집현전** (중앙도서관 그룹스터디룸) | 4~10인 14개실, 1일 2시간 제한, 도서관 홈페이지 + 전용 앱 예약 | 온라인 시스템은 있으나 도서관 앱 안에만 존재. 경쟁이 치열해 "빈 시간 찾기"가 사실상 수작업 |
| **공학설계실습실** (전자정보공대) | 별도 예약 없이 이용, 학기 중 09:00–12:00 / 13:00–16:00 | 조회 수단이 없어 직접 가봐야 자리 유무를 앎 |
| **전자정보공대 강의실** | 학부 홈페이지의 별도 "강의실예약안내" 페이지 + 이용 규정 | 도서관과 완전히 다른 채널 |
| **광운창작소** (창업지원센터 메이커스페이스, 3D프린터 보유) | 전화(02-941-9601) / 이메일 / 카카오톡 채널 채팅, 사전 연락 필수 | 온라인 예약 시스템 자체가 없음 |
| **로봇학부 실습실·납땜 공간** | 웹 공개 정보 없음 → 학과사무실 문의 / 게시판 공지 | 정보의 존재 자체가 학생에게 안 보임 |

> 위 내용은 공개 검색 결과 기반의 1차 조사이며, **각 항목의 최신 운영 규정은 팀이 직접 방문·문의해 확인한다.** 이 확인 작업이 곧 본 프로젝트의 핵심 자산인 1차 데이터가 된다.

### 한 문장 문제 정의
> **"오늘 저녁 6명이 2시간 쓸 공간"을 찾으려면 학생은 도서관 앱·학부 홈페이지·전화·카카오톡·학과사무실을 각각 따로 뒤져야 한다.**

### 이 문제가 진짜인 이유
- 팀 프로젝트 과목이 늘면서 4~8인 회의 공간 수요가 상시 발생하는데, 집현전은 1일 2시간 제한 + 14개실뿐
- 3D프린팅·납땜은 "장비가 어디 있는지"보다 **"언제 열려 있고 누구에게 연락해야 하는지"** 를 모르는 게 실제 병목
- 신입생·타 학부생은 그 정보에 접근할 경로가 아예 없음

## 2. 무엇을 만드는가 (What)

### 핵심 설계 판단 ⚠️
학교 각 시스템에 **대신 예약을 넣어주는 것은 기관 협조 없이 불가능**하다.
따라서 이 서비스는 **"예약 대행"이 아니라 "조회 · 판단 · 안내" 레이어**로 정의한다.
→ 사용자는 우리 서비스에서 **어디가 가능한지 판단**하고, **해당 채널로 한 번에 점프**한다.

### 3단계 데이터 계층 (Tier 모델)

| Tier | 대상 | 우리가 제공하는 것 |
|---|---|---|
| **T1 자동** | 온라인 예약 시스템이 있는 공간 (집현전 등) | 공개된 잔여 현황을 주기적으로 동기화해 표시 + 예약 페이지 딥링크. *기술·정책상 불가 시 T2로 강등* |
| **T2 운영정보** | 개방시간·규정이 고정된 공간 (공학설계실습실 09–12/13–16 등) | 팀이 조사한 운영 데이터를 DB화해 **"지금 열림/닫힘"** 을 자동 계산 |
| **T3 제보** | 전화·카톡 예약이거나 정보가 없는 공간 (광운창작소, 학부 실습실) | 연락 채널 원클릭(전화 걸기 / 카톡 채널) + 사용자 혼잡도 제보("한산/보통/붐빔") |

> 이 Tier 모델이 본 프로젝트의 지적 기여다. "통합이 안 되는 대상을 어떻게 통합된 경험으로 보이게 할 것인가"에 대한 답.

### MVP 기능 (반드시 구현)

1. **지금 현황 보드** — 공간 카드 목록에 열림/닫힘·혼잡도·예약채널 배지 표시
2. **조건 검색** — `인원수 / 이용 날짜·시간 / 필요 설비(화이트보드·콘센트·모니터·3D프린터·납땜스테이션)` 입력 → 가능한 공간 랭킹
3. **팀플 모드** — "6명, 오늘 19시, 2시간" 한 줄 입력으로 후보 3곳 즉시 제시 (집현전 2시간 제한 등 규정 반영)
4. **상세 화면** — 사진, 수용인원, 설비, 운영시간, 이용 규정, **예약 방법 원클릭 실행**(예약 페이지 링크 / 전화 걸기 / 카톡 채널)
5. **캠퍼스 지도** — 카카오맵 API로 건물 마커 + 현재 이용 가능 여부 색상 표시 (영업중=초록 / 종료=회색)
6. **혼잡도 제보** — 로그인 없이 3초 안에 제보, 최근 제보 시각 함께 표시

### 확장 기능 (여유 시)

7. **장비 상태 보드** — "3D프린터 2번 고장", "필라멘트 소진" 제보 공유
8. **즐겨찾기 + 오픈 알림** — 관심 공간이 열리면 알림
9. **관리자 화면** — 운영시간·규정 변경 반영, 각 정보의 **최종 확인일** 표기

### 범위 밖 (명시적으로 안 함)
- 학교 계정 연동 및 실제 예약 트랜잭션 대행, 결제
- 네이티브 모바일 앱 (반응형 웹으로 대체)
- 좌석 단위 실시간 센서/카메라 기반 인원 감지
- 하드웨어·회로·기구 설계

## 3. 그래서 무엇이 좋아지는가 (Value)

- 5개 채널을 뒤지던 탐색이 **한 화면 한 번의 입력**으로 바뀐다
- 학생에게 아예 안 보이던 정보(학부 실습실 개방시간, 창작소 연락 경로)가 **처음으로 한곳에 정리된다**
- 수집한 공간 데이터셋 자체가 학과·학생회에 넘길 수 있는 **재사용 가능한 산출물**이 된다

## 4. 목표 (측정 가능하게)

- 캠퍼스 공간 **60곳 이상**을 수용인원·설비·운영시간·예약채널까지 포함해 DB화
- 조건 입력 → 후보 제시까지 **3초 이내**
- 사용자 테스트 **20명 이상**, "다음에도 쓰겠다" 응답 **70% 이상**
- 운영 기간 중 혼잡도 제보 **100건 이상** 수집
- 최종 발표에서 **현장 즉석 조건 입력 데모 성공**

## 5. 기술 스택 (전부 무료 / 저비용)

- 프론트: React + TypeScript + Vite, 반응형(모바일 우선 — 학생은 걸어다니며 쓴다)
- 지도: **카카오맵 API**(무료 / A팀 선례 있음, 네이버는 유료 전환으로 제외)
- 백엔드: FastAPI 또는 Next.js API Route
- DB: PostgreSQL (Supabase 무료 티어)
- 배포: Vercel 무료 티어
- 협업: GitHub(코드·이슈), Notion / Google Drive(자료), Figma(와이어프레임)
- 개발 도구: Cursor, Claude Code

## 8. 위험 및 대응 (Risk)

| 위험 | 대응 |
|---|---|
| **T1 자동 동기화가 기술·정책상 막힘** | 학교 시스템에 부하를 주는 크롤링은 하지 않는다. 이용약관·robots.txt 확인 후 불가하면 즉시 T2/T3로 강등 — 서비스 구조가 이미 이를 전제로 설계됨 |
| **제보 데이터 콜드스타트** (초기에 제보가 없음) | 운영시간 기반 기본값을 항상 표시 + 팀원 8명이 시드 제보 + 학부 커뮤니티·단톡방 홍보 |
| **정보 변동** (학기마다 개방시간이 바뀜) | 모든 정보에 "최종 확인일" 표기 + 관리자 화면으로 즉시 수정 가능하게 |
| **학과·부서 정보 제공 거절** | 공개 정보만 사용하고, 비공개 항목은 "학과사무실 문의" 안내로 대체 |
| **난도가 낮아 결과물이 밋밋해짐** | 기술 난도가 아니라 **데이터 커버리지(60곳)와 UI 완성도**를 성과 지표로 삼는다. 조사 범위를 먼저 확정하고 줄이지 않는다 |
| 개인정보 | 로그인 없이 익명 제보(중복 방지는 브라우저 토큰), 개인정보 수집 0 |
| 통합 지연 | 매주 화요일 회의에서 `main` 통합 강제, 개인 브랜치 1주 이상 미병합 금지 |

## 11. 최종 발표 데모 시나리오 (5분)

1. 문제 제기 — 5개 채널 스크린샷을 한 장에 나열: "공간 하나 잡는 데 앱 1개, 홈페이지 2개, 전화 1통, 카톡 1개"
2. 화면 전환 → 심사자에게 조건 입력 요청: **"6명, 오늘 19시, 2시간, 화이트보드 필요"**
3. 후보 3곳이 순위로 뜨고, 지도에 초록/회색으로 표시되는 장면
4. 1순위 집현전 → **예약 페이지로 바로 점프** / 3순위 광운창작소 → **전화 걸기 버튼**
5. 두 번째 시나리오: **"지금 3D프린터 쓸 수 있는 곳"** → 운영시간 + 최근 제보가 함께 뜨는 화면
6. 성과 정리 — 조사 공간 60곳, 사용자 테스트 20명 결과, 수집 제보 100건 그래프
